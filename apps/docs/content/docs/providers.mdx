---
title: 'S3-compatible providers'
description: 'Cloudflare R2, MinIO, Scaleway, Wasabi — the endpoint is the only difference.'
---

Set `endpoint` and s3nd adjusts three defaults for you:

- `region` becomes `"auto"`, which is the convention for providers that ignore the region but
  whose SDK still demands one.
- `forcePathStyle` becomes `true` — `https://endpoint/bucket/key` rather than
  `https://bucket.endpoint/key`. Self-hosted gateways require it and managed providers accept it.
- Checksums are only sent and checked when an operation requires them. See below.

The first two stay overridable; for the third, bring your own client.

## Checksums

Since `@aws-sdk/client-s3` 3.729, the SDK adds a CRC32 checksum to every request (sent as a
trailer on streaming, `aws-chunked` bodies) and validates the ones that come back. AWS supports
that; Cloudflare R2 and older MinIO or Ceph builds may not, and the symptom is a 400, a
`XAmzContentSHA256Mismatch` or a `NotImplemented` on every upload.

So when you set an `endpoint`, the client s3nd creates uses
`requestChecksumCalculation: 'WHEN_REQUIRED'` and `responseChecksumValidation: 'WHEN_REQUIRED'`.
Plain AWS (no `endpoint`) keeps the SDK defaults. A `client` you pass in is used as is, so if you
build your own for R2, set the same two options on it:

```ts
const store = createBucket({
  bucket: 'my-bucket',
  client: new S3Client({
    region: 'auto',
    endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
    requestChecksumCalculation: 'WHEN_REQUIRED',
    responseChecksumValidation: 'WHEN_REQUIRED',
  }),
})
```

## Cloudflare R2

```ts
const store = createBucket({
  bucket: 'my-bucket',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: process.env.R2_ACCESS_KEY_ID!,
    secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
  },
  publicUrl: 'https://cdn.example.com', // your R2 custom domain
})
```

R2 has no egress fees, which makes the public-URL path particularly attractive: upload through
your server, serve through the custom domain. [Without a server](/docs/no-server) sets the same
bucket up for the CLI alone — no deployment in the middle at all.

## MinIO

```ts
const store = createBucket({
  bucket: 'my-bucket',
  endpoint: 'http://localhost:9000',
  credentials: { accessKeyId: 'minioadmin', secretAccessKey: 'minioadmin' },
})
```

A local MinIO is the cheapest way to exercise the real code path in development and in CI.
MinIO no longer publishes community images or binaries, so build it from source (Go required), or
run an image you already trust:

```sh
go install github.com/minio/minio@latest
MINIO_ROOT_USER=minioadmin MINIO_ROOT_PASSWORD=minioadmin ~/go/bin/minio server ./data
```

s3nd's own CI runs its integration suite against MinIO on every pull request: uploads of a buffer
and of a stream, snapshots, `ifMatch` and `ifAbsent` (MinIO honours `If-None-Match: *` on
`PutObject`), presigned URLs, batched deletes and a transfer handler round trip.

## Scaleway Object Storage

```ts
const store = createBucket({
  bucket: 'my-bucket',
  region: 'fr-par',
  endpoint: 'https://s3.fr-par.scw.cloud',
  credentials: {
    accessKeyId: process.env.SCW_ACCESS_KEY!,
    secretAccessKey: process.env.SCW_SECRET_KEY!,
  },
})
```

Scaleway does use the region, so pass it explicitly rather than letting it default to `"auto"`.

## Wasabi

```ts
const store = createBucket({
  bucket: 'my-bucket',
  region: 'eu-central-1',
  endpoint: 'https://s3.eu-central-1.wasabisys.com',
  credentials: {
    accessKeyId: process.env.WASABI_ACCESS_KEY!,
    secretAccessKey: process.env.WASABI_SECRET_KEY!,
  },
})
```

## A note on ACLs

`upload()` accepts an `acl` option, but most buckets created after 2023 have ACLs disabled —
AWS turns on "bucket owner enforced" by default, and R2 has no ACL support at all. Setting `acl`
on such a bucket fails the request. Make objects public with a bucket policy or a CDN in front,
and leave `acl` alone.
